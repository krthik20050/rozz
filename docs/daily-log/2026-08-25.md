# Daily Log — 2026-08-25

## Chat red-screen crash fixed (root-caused + regression-tested)

### Symptom
Typing a message in the ROZZ chat and getting a reply threw — the app showed
the red error screen (assertion in debug, TypeError in release). Any assistant
answer crashed, so the chat was effectively unusable.

### Root cause
`ChatRozzPage._mdStyle()` built the markdown style sheet via
`MarkdownStyleSheet.fromTheme(...)`. That factory **asserts**
`theme.textTheme.bodyMedium?.fontSize != null` (style_sheet.dart line 102) and
later does `fontSize!` on it for code blocks. In current Flutter
(3.41 / Dart 3.11) the default `ThemeData.dark().textTheme` leaves font sizes
**unset** (only family/color are defined), so the assert fired on *every*
assistant bubble render. The crash happened only at runtime — `flutter analyze`
and the pure-Dart tests never exercised widget rendering, so CI stayed green.

### Fix
`_mdStyle()` no longer uses `fromTheme`. It constructs `MarkdownStyleSheet`
directly with explicit font sizes (DM Sans body 14, Syne headings, DM Mono
code/tables), plus explicit `a`/`del`/headings/blockquote/img/checkbox styles
that `fromTheme` used to supply. Rendering is now deterministic and no longer
depends on the ambient theme's (null) font sizes.

### Tests
New `test/features/chat/presentation/pages/chat_rozz_page_test.dart` (4 widget
tests) — the first real widget coverage for the chat:
- sending a message and rendering a streamed reply doesn't throw
- a markdown **table** reply renders without throwing (the exact crash path)
- a stream error surfaces the fallback message, not a crash
- the no-key setup screen renders and the composer still works

The table test failed before the fix (reproduced the assertion) and passes now.

130 tests passing (126 existing + 4 new), `flutter analyze` clean.
