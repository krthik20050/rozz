## Part A — Three fixes (earlier today, see `current.md`)

### What changed

- **Home balance freeze fixed** — `getLastKnownBalance()` preferred the EOD
  snapshot over a transaction's `balance_after` unless strictly newer. The
  WorkManager EOD task writes a *same-day* mid-day estimate into `mab_history`,
  so once that row landed, every same-day transaction lost and the balance froze
  all day. Now a same-day transaction wins (`>=`). Tests updated.
- **Chat blank replies fixed** — GROQ's `openai/gpt-oss-120b` is a hidden-CoT
  reasoning model. The request sent `max_tokens` (wrong field; GROQ uses
  `max_completion_tokens`) so the 1024 budget vanished inside thinking and every
  reply came back empty with `finish_reason: length`. Streaming also ignored
  `delta.reasoning_content`. Now: `max_completion_tokens` (2048),
  `include_reasoning: false` on GROQ chat/stream paths, `sseDeltas` test covers
  reasoning deltas.
- **MAB fine formula corrected** — was a stepped ₹600/₹750/₹1,200 schedule
  (always ≥₹600, wrong). HDFC's actual Regular Savings charge is **6% of the
  shortfall, or a cap, whichever is lower** — ₹600 metro/urban, ₹300
  semi-urban/rural — + GST. `EstimateMabFine` now computes
  `min(shortfall × 6%, cap)`; user-reported real penalty ₹200–300 matches.
- 126 tests passing, `flutter analyze` clean.

### Root cause

- GROQ free tier for `openai/gpt-oss-120b` caps at **8000 TPM**, and GROQ counts
  TPM as *input tokens + max_completion_tokens*. The chat context builder injects
  the **FULL transaction ledger** (every row, newest first) into the request →
  exceeds 8000 → GROQ rejects with 413. Real error body (GROQ docs / GitHub
  issues): `"Request too large for model ... on tokens per minute (TPM): Limit
  8000, Requested NNNNN"`.
- Note: the earlier `max_completion_tokens` raise to 2048 worsened the request
  size (reserved output counts toward TPM).

### Fix applied (two files)

- **`lib/features/chat/presentation/pages/chat_rozz_page.dart`** — `_buildContext`
  now caps the ledger to the latest **100** rows
  (`static const _maxLedgerRows = 100`) and tells the model how many were shown
  vs omitted ("latest 100 of N shown — the rest are omitted") so it doesn't treat
  a truncated list as complete.
- **`lib/core/services/ai_service.dart`** — the non-200 stream path now reads +
  logs the actual response body (GROQ puts the real reason there, e.g. the TPM
  limit) instead of a bare status code.
